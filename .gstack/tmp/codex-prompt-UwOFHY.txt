## Recommended Approach

**Approach B**, structured as six audit phases:

- **Phase 0 — Access & Instrumentation (founder: ~1h; the only founder-blocking step; sub-cap $15).** Founder assembles the access bundle: **full WP admin login (or hosting panel/FTP/SSH credentials)** — an application password alone cannot install instrumentation; payment-records export (any format); 7-day Telegram support sample (screenshots or forward); analytics access if any exists. AI installs sanctions-safe measurement — **primary: a lightweight WP-native analytics plugin (the site is already in a performance crisis; no new server-side stack on production); self-hosted Matomo only if hosted OFF the production server; Microsoft Clarity only if a reachability check from an Iranian IP passes** (US services are frequently blocked for Iranian users). Install path: code-snippet plugin (e.g. WPCode) or child-theme snippet — full site backup confirmed first, rollback steps written down before the write. Phase 0 also verifies **admin-side reachability from this box** (wp-admin / hosting panel / SSH — Iran-hosted servers often firewall foreign IPs in both directions); fallback: Iranian-IP proxy or founder-side execution of the paste-ready install.
- **Phase 1 — Money Flow tracer bullet (CC: 2-3 days; sub-cap $70).** Pre-check: fetch one page via an Iranian-IP proxy vs directly from this box; if behavior differs, all journeys run through the proxy. Full Playwright crawl of both properties (mobile-first, Persian locale); map every CTA, pricing path, checkout path, dead link, form collision, missing image, untranslated string; synthetic buyer journeys with screenshots pinpointing where purchase intent dies — **journey endpoint: reaching the payment-gateway handoff with a valid cart** (payment cannot be completed from abroad without an Iranian card; the final leg is covered by one founder-side screen-recorded real purchase attempt, ~10 min, counted inside the 6h founder budget); payment-record analysis (what actually sold, when, via what path, at what price); output: **Revenue Evidence Report** — standalone, actionable, the audit's first deliverable.
- **Phase 2 — Whole-business evidence sweep (CC: 3-4 days; sub-cap $80).** Remaining processes: support load (Telegram sample categorized per the June 20 taxonomy; **student PII — names, phone numbers, handles — redacted or pseudonymized before anything is stored in gbrain or audit artifacts; the same rule applies to payment-record data (buyer names, phones, card/bank details)**), delivery/success (LearnDash completion data, GamiPress engagement, churn signals), content production pipeline, plugin/performance audit (213 plugins → keep/kill/replace list with risk ratings), financial picture from payment history.
- **Phase 3 — Clarityboard interviews (founder: 3 sessions × ~45-60 min; sub-cap $35).** Only what evidence cannot show: positioning intent, offer logic, pricing history, what was tried and abandoned, the future-fit thesis (what happens to IranFluent as free AI tutors commoditize English instruction), time allocation reality-check. Interviewer posture per the Clarityboard doc: push for specificity, anti-hallucination rules, validation gate before synthesis.
- **Phase 4 — Scoring & ranking (CC: 1-2 days; sub-cap $40).** EMPOWER 7-driver score per process (rubric enumerated below); 4-level documentation gap map (verify/update the January framework); opportunity list typed Automate / AI-Assist / Delegate / Eliminate, ranked by (Time Savings × Impact) ÷ Implementation Difficulty; payback gates: **<12 months = yes; 12-24 months = founder decision, labeled `Needs founder answer`; >24 months = no**; each opportunity carries a token-cost estimate and a `Fix now / Audit deeper / Ignore / Needs founder answer` label (Codex's labels, adopted).
- **Phase 5 — Deliverables (sub-cap $30).** (1) RTL HTML **Audit Dashboard** (Clarityboard-style artifact: process map with RACI, driver scores, ranked opportunities, evidence links); (2) updated Business Process Framework + Resources & Constraints (the living Master Context, stored in gbrain); (3) **Token Allocation Plan** for the remaining ~$750-850, sequenced by rank; (4) go/no-go recommendation on the June 20 Angie AI test, now evidence-based.

**Budget tracking mechanism:** at each phase boundary, log Claude Code session cost (`/cost` output or `ccusage`) into the dashboard's budget table. **The binding cap is the ≤$250 total; per-phase sub-caps are early-warning alarms, not entitlements.** A phase hitting its sub-cap pauses and re-plans against the remaining TOTAL budget, not its own ceiling.

**Scoring rubric (enumerated so Phase 4 does not depend on the stale corpus):**
- *8 core processes:* Market to Lead, Lead to Sale, Sale to Delivery, Delivery to Success, Success to Market (Customer Flow); Financial Performance Management (Money Flow); Hire to Retire, Quality Management + Product Development (People Flow / Robustness).
- *7 EMPOWER value drivers:* Expansion, Marketing, Profitability, Offering, Workforce, Execution, Robustness.
- *4 documentation levels:* Strategy (core-process overview) → Blueprint (functional breakdown) → Guide (step-by-step) → Template (daily artifacts).
- *Scale:* every driver/process score is 1-5 (1 = absent/broken, 3 = functional but undocumented/manual, 5 = documented and AI-executable). Impact and Difficulty in the opportunity formula use the same 1-5 scale.
- *Payback definition:* payback months = (opportunity's token-cost estimate in $ + founder hours × $50/h) ÷ expected monthly gain in the opportunity's target metric ($ revenue, or founder-hours saved × $50/h).

Rationale: it is the deep diagnosis Hiwa explicitly demanded, it front-loads Codex's revenue urgency via the tracer bullet, it converts the founder's total involvement to ~6 bounded hours (the June plan died of founder-ops dependence), and it leaves ≥75% of the budget for execution directed by evidence instead of vibes.
